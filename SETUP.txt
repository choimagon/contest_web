IMEL — 개인 대회 제출

기능
  이름 입력, .py 파일 선택/드래그앤드롭, 제출, 제출 목록, 이름 검색, 새로고침.
  목록은 이름과 파일명, 한국 시간 기준 제출 시각(초까지), 결과를 표시합니다.
  결과는 현재 X로 표시하는 자리이며, 결과 저장·채점 기능은 포함하지 않습니다.
  상단 예약 영역은 빈 공간으로 유지합니다. 밝은 아이보리·살구색과 오렌지 강조색, 둥근 카드 스타일을 사용합니다.
  웹은 파일 내용을 읽거나 분석·미리보기·실행·다운로드하지 않습니다.
  로그인이나 회원가입 없이 누구나 제출하고 이름·파일명 목록을 조회할 수 있습니다.

실행
  npm run dev
  http://localhost:5173

Vercel
  GitHub 저장소를 Import하고 Root Directory를 저장소 루트로 지정합니다.
  vercel.json: Framework Other / Build npm run build / Output dist
  별도 npm 의존성을 설치할 필요가 없습니다.
  전달받은 Supabase URL과 Publishable 공개 키가 supabase/public-config.json에 있습니다.
  Vercel의 SUPABASE_URL / SUPABASE_PUBLISHABLE_KEY 환경 변수로 덮어쓸 수 있습니다.
  비밀 키나 service_role 키는 프런트엔드 및 이 저장소에 넣지 않습니다.

Supabase
  supabase/schema.sql: 제출 테이블, 비공개 파일 버킷, 접근 권한, 제출 등록 RPC.
  초기 허용 이메일: magon8696@naver.com
  공개 제출에는 Supabase Auth 계정이나 Anonymous Sign-Ins 설정이 필요하지 않습니다.
  관리자용 원본 테이블 조회는 확인된 허용 이메일 계정에만 열려 있습니다.

저장 구조 — 나중에 만들 라이브러리용
  Postgres public.team_submissions:
    id              UUID, 제출 ID
    team_name       제출자 이름 (기존 DB 컬럼명 유지)
    file_name       업로드한 원래 .py 파일명
    file_size       파일 크기(바이트), Storage 메타데이터에서 확인한 값
    storage_bucket  team-python-files
    storage_path    public/<비공개 업로드 토큰 UUID>/<제출 UUID>.py
                    기존 로그인 제출은 <사용자 UUID>/<제출 UUID>.py 유지
    submitted_by    공개 제출은 null, 기존 로그인 제출은 Auth 사용자 UUID
    created_at      제출 시간

  파일 자체는 Supabase Storage의 비공개 team-python-files 버킷에 보관됩니다.
  라이브러리는 서버에서 승인된 관리자 권한으로 team_submissions를 조회하고,
  storage_bucket + storage_path를 사용해 원본 파일을 가져올 수 있습니다.
  로그인 여부와 관계없이 브라우저에는 해당 버킷의 파일 읽기 권한을 부여하지 않습니다.
  라이브러리 코드는 이번 웹 프로젝트에 포함하지 않았습니다.

제출 동작
  .py 파일 한 개, 최대 5 MB. 파일 내용과 인코딩은 검사하지 않습니다.
  빈 Python 파일(0바이트)도 제출할 수 있습니다.
  동일한 이름 또는 파일명으로 여러 번 제출할 수 있으며 각각 별도 제출 ID로 저장합니다.
  파일 바이트를 Storage API로 전달한 뒤, 등록 RPC가 비공개 업로드 토큰과 객체 존재·크기를 확인합니다.
  DB에는 파일 내용 없이 이름과 파일 메타데이터만 저장합니다.
  업로드와 목록 등록 사이에 연결이 끊기면 복구 정보(이름·ID·크기·비공개 업로드 토큰만)를 브라우저에 남깁니다.
  '목록 등록 다시 시도'로 같은 제출을 재등록하며 중복 레코드를 만들지 않습니다.

접근 제어
  submission_private.allowed_emails는 브라우저에서 읽거나 수정할 수 없습니다.
  허용 이메일 추가/제거는 SQL Editor에서 관리자만 수행합니다.
    추가: insert into submission_private.allowed_emails(email) values ('허용이메일') on conflict do nothing;
    제거: delete from submission_private.allowed_emails where email = '제거이메일';
  공개 업로드는 지정된 UUID 경로의 새 객체 생성만 허용합니다. 기존 파일 덮어쓰기는 차단합니다.
  list_public_team_submissions RPC는 id·team_name·file_name·file_size·created_at만 반환합니다.
  register_public_team_submission RPC는 업로드 토큰을 확인하고 동일한 공개 메타데이터만 반환합니다.
  업로드 토큰과 storage_path는 공개 목록에 노출하지 않습니다.
  원본 테이블 직접 조회는 허용된 관리자만 가능하며, 브라우저의 직접 입력·수정·삭제는 차단합니다.
  파일은 브라우저에서 읽기·수정·삭제할 수 없습니다. 다른 버킷의 권한에는 영향을 주지 않습니다.
